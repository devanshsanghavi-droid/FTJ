% Fig 2b (v7.1 hero; binding spec ../../DESIGN_V7.md sections 3.3 and 7, worked example ../../fig1/fig1a_pipeline.tex):
% where the crawler attaches. Message: the crawler taps every target before it runs -- the page and both of Shopify's
% pixel sandboxes, which a CMP's script blocker cannot reach -- so it captures, and labels, the requests sent from
% inside the sandboxes.
%
% The store is Fig 1a's, in Fig 1a's arrangement and order, so the eye reads only what is new (the instrumentation):
%   level 1  'Shopify store in the browser': outline-only frame (0.6 pt NEUTRAL), 2.2 mm in from the trim as in Fig 1a.
%            The crawler stands outside it.
%   level 2  'Page (main thread)' (TINT PAGE ground, NEUTRAL outline) across the top, holding the cookie banner (the one
%            tinted box, TINT EVENT with an EVENT outline) and the vendor tags; 'Pixel sandboxes' (TINT SAND ground, SAND
%            outline) below it at the right, under the vendor tags.
%   level 3  boxes sized to text (sciplot S.box: 2.4 x 1.6 mm padding, 0.6 pt SPAXIS, 0.5 mm corners), one width for
%            all four; the web worker above the sandboxed iframe, 3 mm apart (Fig 1a's order and pitch), each with its
%            Shopify runtime ('strict', 'lax') in 6 pt muted grey.
% The instrumentation (new here): the crawler (7 pt 'Crawler', 6 pt muted 'DevTools Protocol' on one line, as Fig 1a's
% gate) drives one bus into the frame, between the two sandboxes, to a fork (Fig 1a's fork idiom: one spine, 0.6 pt
% connectors that stop 0.6 mm short, a 0.8 mm rounded bend): up into the page (its region, midway between its two
% boxes) and right into the web worker and the sandboxed iframe. The bus carries the guarantee that makes the sandboxed
% requests visible, in 6 pt muted grey above it: attached before any script runs.
% The one accent (LEAK, 1.0 pt, the larger Stealth head of Fig 1a's leak arrows): one captured request, a request that
% lost consent (one of Fig 1c's first requests). It drops straight out of the sandboxed iframe and the browser and lands
% on its test code in the request's URL below, shortened to one line (host; '/…&' for the dropped path and parameters;
% the carrier parameter; our test code), named 'Example request' (7 pt muted, left of it on its baseline) and
% right-aligned with the browser frame. Two square brackets (0.6 pt NEUTRAL) key two of the crawler's labels on it in
% 6 pt muted grey: 'vendor' (the host) and 'test code' (where the brick path lands).
% Strings: ../build/fig2_numbers.tex; geometry (checked against measured Arial widths): ../build/fig2_layout.tex.

\newcommand{\Brk}[2]{%
  \draw[brk] ($(#1.west |- 0,-\BBrkTop)+(0.15,0)$) -- ($(#1.west |- 0,-\BBrkBot)+(0.15,0)$)
          -- ($(#1.east |- 0,-\BBrkBot)+(-0.15,0)$) -- ($(#1.east |- 0,-\BBrkTop)+(-0.15,0)$);
  \node[sub, anchor=base] at ($(#1.west |- 0,-\BKeyBase)!0.5!(#1.east |- 0,-\BKeyBase)$) {#2};}
