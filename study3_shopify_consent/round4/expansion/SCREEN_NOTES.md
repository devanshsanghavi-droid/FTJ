## Design

- **List.** Tranco **L5PZ4** (the main sample's list, file already on disk), ranks **200,001-1,000,000** (800,000 domains).
- **DNS flag.** Unchanged from the main sample (`sample/dns_scan.py`): apex or www resolves into 23.227.32.0/19 or CNAMEs to *.myshopify.com; Shopify platform domains dropped. At most 40 lookups in flight.
- **Random order.** Domains were resolved in a seeded random permutation (seed 20260926). A flagged domain was screened only after every domain before it in the permutation had been resolved, so the screened set is always an exact prefix of a uniformly random order of the frame: a simple random sample without replacement.
- **Draw.** The drawn set is the shortest prefix of the order that holds the target number of stratum stores; screened domains after it are `overdraw_not_in_sample` (as in the main sample). Design weight w = N / n = 27,660 / 819 = **33.7729** for every candidate.
- **Eligibility.** As in the main sample (`sample/verify.py`): HTTP 200; Shopify Online Store markers (headless excluded); no password page; adult/child keyword screen; product URL from the homepage. New: duplicates of main-sample or creator-stratum shops (same `Shopify.shop` or host) are excluded, and within the expansion the lowest-permutation domain of a shop is kept.
- **Stratum definition.** An eligible storefront whose Pandectes, OneTrust or Cookiebot configuration publishes a readable blocklist that names at least one advertising vendor (`crawl/vendor_endpoints.json`) as blocked at least after a refusal, AND for which blocking before any choice for a California visitor is declared ('yes': Pandectes v4 ad category in `defaultBlocked`, or v5 with `USCA`/`US` in `regions.strict`) or can only be settled at run time ('unknown': OneTrust active groups, Cookiebot consent state). The rules mirror `crawl/build_tables.py:declared_by_vendor`, which defined the main paper's blocklist row. Stores whose configuration says the list is not applied before a choice in California ('no') are listed separately.
- **Where the lists come from.** Pandectes: inline JSON in the homepage. OneTrust: `OtAutoBlock.js` named in the homepage, fetched once from cdn.cookielaw.org. Cookiebot: `configuration.js` for the page's `data-cbid` (or its California `data-georegions` id), fetched from consentcdn.cookiebot.com. These are the files every visitor's browser loads; vendor robots.txt was checked (both return 4xx = no restrictions).

## Rules followed (ethics request section 5.1 / 5.2)

- One `robots.txt` request and at most **one homepage GET** per store (redirects followed; the robots.txt of each new host was checked before each hop). RFC 9309 matching for product token `python-requests`; 4xx = allowed; 5xx/unreachable = skipped. No `products.json` request (unlike the main sample), so a store without a product link on its homepage has an empty `product_url`.
- Default `python-requests` User-Agent (no spoofing), no cookies kept, no JavaScript, no retries, no forms, logins, carts or consent clicks.
- Adult and child-directed stores: domain-name screen **before any request**; title/description screen on the fetched page; excluded, not reviewed by the student. Titles of adult-flagged pages were not stored.
- Pacing: at most 1 homepage GET per second overall, at most 2 robots.txt GETs per second overall (different hosts), 6 sites in flight, vendor-CDN GETs at most 1 per second. Each store received at most 1 homepage request (plus redirect hops) during screening.
- Storage: homepages kept only for blocklist stores (gzipped); free-disk floor 1.2 GB enforced by the screener.

## Validation of the static screen against the main crawl

On the 1,400 main-sample stores, applying this screen to the homepages saved at sampling time (and the OneTrust/Cookiebot files the crawl captured):
- Readable ad blocklist, static vs run time: both 54, static only 0, run time only 4, neither 1342 (sensitivity 93.1%, no false positives).
  The misses are OneTrust stores whose `OtAutoBlock.js` is injected by script rather than named in the HTML, and one Pandectes store whose settings load from a file.
- All 21 stores of the paper's blocklist row (declared blocked before any choice at run time) are in the static stratum: 'yes' 15, 'unknown' 6.
- Static 'yes' was confirmed at run time on 15 of 15; 'unknown' on 6 of 11; static 'no' never showed pre-choice blocking (0 of 28).

## Expected size at measurement

- Applying the main crawl's confirmation rates (static 'yes' 15/15, 'unknown' 6/11) to the 12 candidates (11 'yes', 1 'unknown') predicts about **12** stores whose blocklist is in force before any choice at run time.
- In the main crawl, 7 of 21 such stores had the CMP itself write 'marketing: yes' without a click and left the primary analysis; at that ratio the primary (no-'yes') expansion sample would be about **8** stores, added to the main study's 14.
- The stratum is much rarer in ranks 200k-1M than in the main sample: most Pandectes installs there have the blocker switched off, and most OneTrust installs load no `OtAutoBlock.js`. The target of 250 stores (and 150+ primary) was therefore not reached when the screen stopped.

## Deviations and incidents

- **12 records lost (nonresponse).** In the first run (06:52-06:55 UTC, 27 Sep 2026) the stop path of `screen.py` discarded the results of 12 sites whose homepage had already been fetched once. They were not fetched again (one homepage request per site); they are in the drawn prefix as `lost_not_refetched` and treated as nonresponse. The bug was fixed before the restart (the stop path now drains and records every submitted site). Their note field in `raw/screen_results.jsonl` gives a wrong time (06:59-07:01); the correct window is 06:52-06:55 UTC.
- The robots.txt rate was raised from 1 to 2 per second at the restart (different hosts each; homepage GETs stayed at 1 per second).
- Unlike the main sample, no `products.json` request was made, so a candidate without a product link on its homepage has an empty `product_url`; the measurement crawl must resolve it within the per-site limit of 8 loads, or measure the homepage.

## Limitations

- Static screening misses blocklists that are only visible at run time (about 1 in 15 in the main sample: OneTrust auto-blocking injected by script; Pandectes settings loaded from a file). Those stores are outside the stratum as defined here, so the stratum is 'stores whose blocklist is visible in the served HTML or in the file it names'.
- 'Unknown' pre-choice status (OneTrust, Cookiebot) is settled only by the measurement crawl; in the main crawl about half of such stores applied the list before a choice.
- The adult/child screen is the main sample's keyword screen; no human review was done. Candidates with an age-gate hint are flagged for the mentor.
- Weights assume one frame domain per shop; within-expansion duplicates were removed, but a shop reachable from two frame domains has twice the inclusion probability (rare; ignored).
- One vantage point (California); no EU/UK run.
