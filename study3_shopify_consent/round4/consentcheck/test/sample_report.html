What we found

  • Problem 3 ad vendors received data before the visitor chose

    Your banner asks visitors to choose, but Google Ads / DoubleClick / Floodlight, Microsoft Advertising UET (Bing), Meta (Facebook/Instagram) sent requests before any choice was made; Google Ads / DoubleClick / Floodlight, Microsoft Advertising UET (Bing) did so from Shopify's pixel sandbox, which your consent app's script blocking cannot reach. Shopify's own setting for this visitor's region was "allowed until the visitor opts out", so Shopify let the pixels start.

    See fixes: 1, 2

  • Problem Decline did not stop Google Ads / DoubleClick / Floodlight

    On a fresh page after the Decline, Google Ads / DoubleClick / Floodlight started again and sent data. "PM Conversions" declares no purpose, so no choice can stop it.

    See fix: 3

  • Problem GPC did not stop Google Ads / DoubleClick / Floodlight, Microsoft Advertising UET (Bing)

    With the browser's Global Privacy Control signal on, Google Ads / DoubleClick / Floodlight, Microsoft Advertising UET (Bing) still sent data. "PM Conversions" declares no purpose, so no choice can stop it. "uet_custom_pixel_prod" declares marketing but not data sale, and Shopify applies GPC only to pixels that declare data sale. "bing_ads_storea" declares analytics + marketing but not data sale, and Shopify applies GPC only to pixels that declare data sale.

    See fixes: 3, 4

  • Problem 4 installed pixels declare no consent purpose

    "app (API client 2632399)" (app pixel), "gtm_pixel_storea_prod" (custom pixel), "PM Conversions" (custom pixel), "storeaapps_pixel" (custom pixel) declare no privacy purpose to Shopify, so Shopify starts them regardless of what the visitor chooses; "PM Conversions" (custom pixel) sent ad data in this test.

    See fixes: 3, 5

  • Warning Pixels started before your consent app said "no"

    Your consent app told Shopify "no" automatically, but only 1.3 s after the page started; a sandboxed ad pixel had already sent data at 1.0 s. Shopify never stops a pixel that has already started.

    See fixes: 1, 2

  • Warning Microsoft Advertising UET (Bing) kept sending for a while after the Decline

    Pixels that had already started before the click kept sending on the same page (or as the page unloaded). They stopped on the next page. Pixels that never start before a choice avoid this.

    See fixes: 1, 2

  • Warning 2 ad pixels declare marketing but not "data sale"

    "uet_custom_pixel_prod" (custom pixel), "bing_ads_storea" (custom pixel) are not treated as a sale or sharing of data, so GPC and "Do not sell or share" opt-outs do not stop them.

    See fix: 4

  • Note Vendors received the full page address

    Google Ads / DoubleClick / Floodlight, Microsoft Advertising UET (Bing) received the page address including its query string (ConsentCheck's test tag was found in their requests). Shopify passes the full URL to pixels; campaign codes and any personal data in URLs travel with it.

What to fix, in order

  1. 1. Make Shopify's default match your banner

    1. In Shopify admin, go to Settings > Customer privacy and review the cookie banner / consent settings for the regions where your banner asks visitors to choose.
    2. If visitors there should be asked before tracking, set those regions so that tracking requires consent; Shopify then holds marketing pixels until the visitor accepts.
    3. Keep only one banner: if you use a third-party consent app, Shopify recommends disabling its own banner.

    Shopify documentation: help.shopify.com/en/manual/privacy-and-security/privacy/customer-privacy-settings/privacy-settings

  2. 2. Have your consent app report the initial state before pixels start

    1. Ask your consent app vendor whether it reports "no" (or "not yet") to Shopify as soon as the page starts, for visitors who have not chosen.
    2. Where it cannot, rely on Shopify's own region setting (next fix) so that pixels wait by default.

    Shopify documentation: shopify.dev/docs/api/customer-privacy

  3. 3. Set a privacy purpose on every custom pixel

    1. In Shopify admin, go to Settings > Customer events and open the Custom pixels tab.
    2. Open each pixel listed above as declaring no purpose, find Customer privacy > Permission, choose "Required" and tick the purposes the pixel serves (Marketing for ad pixels; Analytics for measurement).
    3. Under Customer privacy > Data sale, keep "qualifies as data sale" for advertising pixels (this is the default for new custom pixels), then save.

    Shopify documentation: help.shopify.com/en/manual/promoting-marketing/pixels/custom-pixels/manage · help.shopify.com/en/manual/promoting-marketing/pixels/custom-pixels/code

  4. 4. Mark ad custom pixels as "data sale"

    1. In Settings > Customer events > Custom pixels, open each advertising pixel listed above.
    2. Under Customer privacy > Data sale, choose the option saying the data collected qualifies as data sale, then save. Shopify then stops the pixel for visitors who opted out, including by GPC.

    Shopify documentation: help.shopify.com/en/manual/promoting-marketing/pixels/custom-pixels/code

  5. 5. Ask app developers about purposes (you cannot edit them yourself)

    1. An app pixel's privacy purposes are set by the app developer. Contact the developer of each app pixel listed above and ask it to declare marketing and data sale for advertising data.
    2. Check whether the app has its own consent settings (for example consent mode or limited data use), and turn them on.
    3. If an advertising app cannot declare its purposes, consider replacing it with a custom pixel whose purposes you control, or removing it.

    Shopify documentation: help.shopify.com/en/manual/promoting-marketing/pixels/app-pixels · shopify.dev/docs/api/web-pixels-api/pixel-privacy

  6. 6. Don't rely on script blocking for app and custom pixels

    1. Your consent app's auto-blocking or blocklist only reaches scripts in the main page. App and custom pixels run in Shopify's sandbox (a web worker or hidden iframe) and are controlled only by Shopify's consent state.
    2. Keep the blocklist for theme scripts, but make sure the Shopify integration and pixel purposes (above) are right, because that is what controls the sandbox.

    Shopify documentation: shopify.dev/docs/apps/build/marketing-analytics/pixels

Limitations

  • One visit per condition from one location. Results depend on where the test runs: Shopify and consent apps behave differently by region. Run it from the regions you care about.
  • The test browser is automated and says so (headless Chrome user agent, automation flag on). Some consent apps and pixels behave differently for automated browsers; confirm important results in a normal browser.
  • Only one page is loaded; other pages, checkout and logged-in states can differ. Nothing is added to the cart and no form is submitted.
  • Vendor recognition uses the study's list of about 70 advertising and analytics endpoints; unknown vendors are not counted.
  • Requests are attributed to the sandbox or the main page from browser debugging data; a small share can be misattributed.
  • This is a technical check, not legal advice. Whether a given behaviour is lawful depends on your jurisdiction, your notices and your contracts.
